# Native VAAPI PGS cadence limit

Implemented on the private-deployment source fork; not deployed and not submitted
upstream. This branch adds one filter to the demonstrated PGS hardware-overlay
path. It does not change scheduling, audio selection, video frame rate, text
subtitles, or other hardware backends.

## Mechanism and ownership

FFmpeg's subtitle-to-video heartbeats can send repeated subtitle images through
pixel conversion, hardware upload and scaling more often than the video frame
rate. A measured 12-second 2160p/PGS sample took approximately 25 seconds without
a correction. The native VAAPI builder now inserts the existing `SetFpsFilter`
before those operations, using the requested video cadence when present or the
source frame rate otherwise. Unknown or invalid rates leave the existing path
unchanged; no extra file probe or guessed frame rate is introduced.

This covers `pgs`, `pgssub` and `hdmv_pgs_subtitle` on hardware overlay. Software
overlay and other subtitle codecs retain their existing behavior. Numeric source
frame rates are read by `VideoStream.getNumericFrameRate`, reusing its existing
ratio parser. Other callers of the older defaulting frame-rate method are unchanged.

The deployment companion removes its PGS canvas/cadence correction. That wrapper
previously probed a subtitle packet at the tune-in position and could time out
before launching FFmpeg. Deploy the native change and wrapper removal together.
Unrelated HLS and WebVTT adaptations remain in the companion.

## Validation and limits

- 56 VAAPI pipeline tests pass, including a regression for placing the PGS cadence
  filter before GPU upload/scaling. Server build and changed-file lint pass.
- The reduced wrapper passes its existing WebVTT checks and a regression asserting
  that the PGS transcode command reaches FFmpeg without a preflight probe.
- Commands generated by the modified builder and executed through the reduced
  wrapper produced 12-second HLS samples from the affected 1080p H.264/TrueHD/PGS
  source and a 2160p HEVC/DTS/PGS source with OpenCL HDR tone mapping, on FFmpeg
  8.1.2-etv.4. Both completed with real-time input pacing and preserved the live
  server and wrapper.
- Earlier isolated comparisons showed identical decoded frames with and without
  explicit subtitle canvas sizing when the cadence filter was retained. Removing
  canvas sizing reduced performance headroom but remained faster than real time
  in the measured samples. This does not establish full-episode, client-player,
  multi-stream, other-driver, or older-FFmpeg compatibility.
